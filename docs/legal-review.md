## 3. 한컴 HWP 공개 문서 이용 조건

한글과컴퓨터는 HWP 파일 형식 문서를 공개하면서 다음을 조건으로 둔다.

- 공개 문서를 참고해 만든 결과물의 저작권은 결과물을 만든 개인·단체에 있다.
- 결과물에는 **"본 제품은 한글과컴퓨터의 한글 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다."** 를 제품의 UI, 매뉴얼, 도움말, 소스에 모두 적어야 한다.
- 한컴은 공개 문서와 그 결과물의 정확성을 보증하지 않는다.

rHWP 가 이 공개 문서를 참고했고(rHWP README Notice), 이 앱은 rHWP 를 포함하므로 같은 문구를 적었다.

| 위치 | 기재 |
|---|---|
| UI | 로그인 화면·메인 화면 바닥글, '앱 정보' 화면 고지 |
| 도움말 | '앱 정보' 화면의 사용 도움말 |
| 매뉴얼 | README.md, 이 문서 |
| 소스 | 저장소 `NOTICE`, 앱 핵심 소스 머리 주석(main.tsx, rhwp.worker.ts, editorSession.ts) |

한컴의 HWPX 참조 저장소(hancom-io/hwpx-owpml-model, dvc, Apache-2.0)는 rHWP 가 스펙만 참조했고, 고지는 rHWP 문서가 담당한다(THIRD_PARTY_NOTICES 에 포함).

## 4. 상표

- "한글", "한컴", "HWP", "HWPX"는 한글과컴퓨터의 등록 상표다.
  - 앱 이름 `반곡고 문서 편집기`, 아이콘, 도메인에 이 상표를 쓰지 않는다 (PRD 8.3).
  - 화면의 "HWP/HWPX"는 파일 형식을 설명하는 용도로만 쓴다.
  - 한컴 로고·아이콘을 쓰지 않는다.
  - 상표 고지와 비제휴 고지를 앱 정보 화면, 제3자 고지, NOTICE 에 적었다.
- "Google", "Google Drive", "Chromebook", "Google Workspace"는 Google 의 상표다. 기능 설명에만 쓰고 Google 의 후원·승인으로 보이게 하지 않는다. 로그인 버튼은 Google 이 제공하는 공식 버튼을 그대로 쓴다.
- 학교명 '반곡고등학교'는 학교가 직접 운영하는 서비스라 사용에 문제가 없다. 교표(학교 상징)를 아이콘에 넣을 때는 학교 내부 사용 승인을 받는다.

## 5. 글꼴

- 앱 화면(편집기 바깥)은 디자인 시스템(CNM)에 따라 **페이퍼로지**(본문)와 **프리젠테이션**(제목)을 쓴다. 둘 다 SIL OFL 1.1 로 상업적 사용·웹폰트 사용이 허용되며, 사용자 브라우저가 공개 CDN(jsDelivr)에서 받는다. 앱 정보 화면의 글꼴 목록에 표기했다.
- 편집기는 크롬북에 없는 글꼴을 공개 웹폰트로 대체해 **사용자 브라우저가 공개 CDN(jsDelivr)에서 직접** 받는다. 앱이 글꼴 파일을 수정하거나 재배포하지 않는다.
- 함초롬체(한컴): 무료 사용 가능, 수정·판매·상업적 재배포 금지. 교육 목적 표시에는 문제가 없다고 본다. 다만 CDN 판본은 제3자가 웹용으로 변환한 것일 수 있다.
- 나눔·Noto (SIL OFL 1.1): 사용·임베딩·재배포 허용.
- KoPub (한국출판인회의): 무료 사용 허용.
- PDF 로 저장할 때 Chrome 이 사용한 글꼴의 일부를 PDF 에 포함한다. OFL 글꼴은 허용된다. 함초롬·KoPub 는 문서 임베딩이 통상 허용되나 배포 전 각 라이선스 원문을 확인한다.
- **자체 호스팅으로 바꿀 때**(docs/fonts.md): 함초롬체는 한컴 배포 원본 그대로만 올리고(변환·서브셋 금지), 라이선스 원문을 함께 둔다. 이 경우 재배포 주체가 학교가 되므로 재검토가 필요하다.

## 6. 개인정보

- 근거: 개인정보 보호법. 학교는 교육 목적 범위에서 학생 정보를 처리하고, 처리 내용을 공개해야 한다(처리방침).
- 이 앱의 처리 범위 (자세한 표는 앱의 '개인정보 처리 안내', `docs/privacy.md`):
  - 문서 내용·파일 이름: 서버로 보내지 않음 (구조적으로 업로드 엔드포인트 없음, 테스트로 확인)
  - 서버(운영 서버를 켠 경우): Google 계정 고유번호(sub), 역할, 최근 접속 시각 / 익명 운영 이벤트 90일 / 접속 기록 30일
  - 크롬북 브라우저: 화면 표시용 이름·이메일, 자동 저장 7일, 최근 문서 목록
- 만 14세 미만은 법정대리인 동의가 필요하지만, 고등학생은 대부분 해당하지 않는다. 다만 Google 은 18세 미만 계정의 서드파티 앱 사용에 대해 **학교가 필요 시 보호자 동의를 확보할 책임**을 명시한다. 학교 방침에 따라 가정통신문 등으로 안내·동의를 받는다.
- 처리 위탁: Google Workspace for Education, Google Cloud/Firebase (Google LLC). 학교의 기존 Workspace 계약 범위 안에서 쓰고, 학교 개인정보 처리방침의 위탁 항목에 Google Cloud(Firebase Hosting, Cloud Run, Firestore) 이용을 추가한다. 일부 처리는 국외에서 이루어질 수 있다.
- Google API 사용자 데이터 정책: drive.file 최소 권한, 받은 정보는 문서 편집 기능에만 사용(제한적 사용 요건). OAuth 동의 화면을 '내부'로 두면 Google 앱 검증 대상이 아니다.
- **해야 할 일**: 앱 내 안내는 초안이다. 학교 개인정보 보호책임자가 학교 처리방침과 맞춰 확정한다.

## 7. 학교 자체 코드의 저작권과 라이선스

- 이 앱은 정보부장이 학교 업무로 만들었다. 저작권법의 업무상저작물 규정에 따라 학교(공립학교의 경우 설립·운영 주체) 명의로 공표하면 저작권이 기관에 귀속될 수 있다. 그래서 저작권 표기는 `© 2026 반곡고등학교`, 개발자 표기는 `개발: 반곡고등학교 2026년 정보부장`으로 나눴다.
- 학교 자체 코드의 **공개 라이선스는 정하지 않았다**(모든 권리 보유, `package.json` 의 `UNLICENSED`). 외부 공개 없이 학교 안에서 쓰는 데는 문제가 없다.
- 다른 학교와 공유하거나 GitHub 에 공개하려면: 학교(또는 교육청)의 승인을 받고 MIT 를 권장한다. rHWP 와 같은 라이선스라 조건이 단순하다. 그때 저장소 루트에 `LICENSE` 를 추가하고 `UNLICENSED` 를 `MIT` 로 바꾼다.
- 개발 과정에 Claude Code(AI)를 사용했다. 생성 코드의 권리 관계는 Anthropic 이용 약관을 따르며, 외부 공개 시 AI 사용 사실을 README 에 밝히는 것을 권장한다.

## 9. rHWP 버전을 올릴 때의 법적 점검

1. `npm run build:studio` 가 라이선스 수집까지 실행한다. 카피레프트가 새로 들어오면 여기서 실패한다.
2. upstream `LICENSE` 가 바뀌었는지 확인한다 (MIT 유지 여부). 바뀌었으면 이 문서를 다시 검토한다.
3. upstream README 의 Notice·Trademark 문구가 바뀌었는지 확인하고 `src/branding.ts` 와 `NOTICE` 에 반영한다.
4. 앱 정보 화면의 rHWP 원문(`LicensesScreen.tsx` 의 RHWP_MIT)이 upstream `LICENSE` 와 같은지 확인한다.
